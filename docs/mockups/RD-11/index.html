A project's own overview at /p/coins

You asked for a better page when you go into a project: last edits, a project summary, metrics where they make sense, and recent updates. Each option makes /p/{project} the project's landing page, inside the shell, with a new Overview tab first (Overview · Stories · Preflight · Handbook · Map). All three use coins' real data read on Sun 11 Oct around 21:30. The one exception is production numbers: no project has a production connection in this database, so A and B show sample values (marked) and C shows coins as it is today, with no connection. Each page works at 375px; narrow the window to see how it stacks.

ABriefing reads like a status report

It reads top to bottom. A dated headline sentence says what happened today ("77 commits and 49 preflight runs today, mostly on the preflight runner…"). Then the brief's own "What it is" paragraph, a row of four headline figures with an optional production strip, Needs you beside Live now, and one merged timeline grouped by day. The timeline mixes builds, fixes, docs, approvals, mockup picks and preflight runs, and folds merges. Best if you want to land on the page and understand the state of the project in ten seconds of reading. It has the fewest boxes and the most words.

Data the page needs that doesn't exist yet

  • Story status history. stories.updated_at is the re-index time, not when a status changed, and nothing records transitions. "Approved" and "built" events have to come from git: build commits (feat|fix|test(ID)) flip a story to built, and docs commits whose subject says "approved" or names an option record a pick. That works, but it is a heuristic. A git log -p on the story files' Status: line would be exact but slower.
  • An edits feed. GitReader admits one log form (7 days, subjects only; Shipped this week). Last edits needs --shortstat, a 14-day window, per-day counts and, for B, --name-only and the working copy's uncommitted count. These are new read methods; nothing writes.
  • Preflight verdicts per run. preflight-cost.csv has no verdict. Verdicts are in coins' preflight-runs.csv (one row per gate, 322 runs), which RD-8 already reads for "Ran on". Story-board has no runs CSV, so its overview shows cost rows with no verdict.
  • Production values. No ProdConnection exists in the local database, so every project falls into the "no production" state. The design works either way, but the with-production layout can only be checked with sample numbers until one is connected.
  • The route. /p/{project} is still SB-10's old ProjectPage (projects.show), which RD-9 retires. RD-11 replaces it. The breadcrumb and sidebar project links, which today go to Stories, would point here.
