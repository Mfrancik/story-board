Production dashboard: three layouts

All three show /prod inside the design-A shell from SB-7. The sidebar gains a Production link, shown active, with a connected count (3/4). Every number is an example value, sized for small apps. coins has 4 preset metrics and 1 custom one (Listings live). client-dashboard has 3 metrics and was connected on Sep 25, so its "vs 7 days ago" shows —. asset-track is unreachable: its last good values are greyed, marked "read 3 h ago", and shown with the error. rent-track is listed under "not connected". Refresh works on each project: the section shows a skeleton, then comes back "read just now". Hover a trend line to see a day's value. The dark strip at the top switches to "client-dashboard still loading" (skeleton) and to the empty state. You can also add #loading or #empty to the URL.

Option A: KPI tiles per project

Each project is a section with its own header (name, status, read time, Refresh). Under it, each metric is a tile with a large value, both changes on their own lines, a 30-day line and "read 2 min ago". The grid is 5 tiles wide on desktop and 2 on a phone. It uses the same stat-card look as Home's "In flight" row.

Good: the easiest to read for one project. Each number has room, and error and loading states belong clearly to one section.

Costs: comparing projects means scanning between sections. The page gets tall as projects and metrics grow: about 1,600 px on a phone for three projects.

Option B: comparison table

One table: projects as rows, and Total users, New today, Active today, Logged in today and Custom as columns. Each cell holds the value, "vs yest." and "vs 7 d ago", a sparkline and the read time. The row header holds the status, error and Refresh. A metric a project does not read says "not tracked". rent-track sits in a "Not connected" group at the foot of the table. Below 768 px, each row becomes a card with one line per metric.

Good: the densest view. Everything fits in about one desktop screen, and you can compare "active today" across apps by reading down a column.

Costs: cells are small, so the changes use short labels. The Custom column holds a different metric on each row, so reading down it compares nothing. Every new custom metric either shares that column or adds a new one. The phone layout is effectively a second design to build.

Option C: metric focus

Choose a metric with the pills: Total users, New today, Active today, Logged in today or Listings live. A headline number totals it across your apps ("521 total users across 3 apps"). Below it, one 30-day chart shows every project's line, with a legend and labels at the line ends. A toggle switches to "Each on its own scale", three small charts side by side. The table underneath has a row per project: value, both changes, a sparkline, the read time and Refresh.

Good: the only option that answers "how are my apps doing together". Growth is easy to compare over time, and the headline gives one number to check each day.

Costs: you see one metric at a time, so reading all of coins takes five clicks. On one shared scale, coins (412) flattens the small apps (23), which is why the per-project scale toggle exists. A custom metric that only one project has makes a chart with a single line. The big chart is the most code to build.

The same in every option

  • Changes are signed and carry an arrow (▲ +9, ▼ −8, ±0), so direction never depends on colour alone. "—" means there is no snapshot for that day.
  • Each project keeps one colour everywhere: coins blue, client-dashboard orange, asset-track aqua. These are the first three slots of the dataviz reference palette, checked with the validator (all pairs, light and dark). Aqua is under 3:1 contrast on white, so it is never the only label.
  • Trend lines are inline SVG with no chart library: 2 px lines, a ringed end dot, a 10% area fill, and a hover readout for each day. A stale (unreachable) value is grey in A and B. In C it is a hollow end dot, because the history is still good and only today's value is old.
  • Worth deciding at build time: "New today", "Active today" and "Logged in today" are counts so far today, compared with yesterday's full day (the 23:55 snapshot). Around 14:00, "▼ −8 vs yesterday" is normal and does not mean a bad day.
