SB-17 · design mockup gate

Production connection and metrics: three placements

All three extend /projects (SB-12) inside the design-A shell and use coins as the example. Each shows the same pieces: the connection form (the password reads "saved — leave blank to keep" when editing, SSL is on by default), Test connection with its three results, the CREATE USER … GRANT SELECT one-liner with a Copy button, the four presets with table and column pickers and a Test button, a custom SQL metric that passes, and one that is refused ("one SELECT only"). The column names are coins' real ones (users.last_seen_at, users.last_login_at, user_login_events.user_id / occurred_at). Every number, host and timing is an example value.

The dark strip at the top of each option switches the form between new and edit (saved), and sets what Test returns: pass, refused (INSERT found) or unreachable. Things to try: press Test connection and Save connection; switch New today on; change Logged in today's table to users and pick last_login_at; press Test on both custom rows; press Remove connection.

Option A: inline expanding row

The row gains a Production column ("Read-only · 4 metrics" or "Not set up"). Clicking it opens a panel under the row: the connection form and result on the left, the one-liner and how read-only is kept on the right, and the metrics list below. The SQL for each preset hides behind "Show SQL".

Good: you never leave the list, which is the closest fit to SB-12's own inline form. It is the least new UI.

Costs: the open panel is very tall and pushes the other projects far down. At about 15 fields plus metrics, it goes past the standards' "simple record" size for in-place editing.

Option B: side drawer

The same Production column opens a slide-over from the right (full screen on a phone) with two tabs, "1 · Connection" and "2 · Metrics". The actions for the open tab sit in a sticky footer. The one-liner is a fold-out that starts open for a new connection. Presets are cards: switched off they collapse to one line, switched on they show the pickers, the SQL and Test.

Good: the list stays put behind it, and the tabs keep each step short. Save and Test are always in reach without scrolling.

Costs: a slide-over is a new pattern, since the board has only modals. The test result and the metrics are never on screen together, and custom SQL gets a narrow editor.

Option C: its own page

The row's Production link goes to /projects/coins/production, with a breadcrumb back. The page is three numbered steps: create the user, connect, pick metrics. Presets are a table with the pickers and generated SQL in place. A sticky column on the right previews the tiles SB-18 will show, filled from each Test, and holds Remove. The strip switches between the list and the page.

Good: it follows the standards' rule for complex forms (more than ~6 fields means a dedicated page). It has the most room for SQL, and the preview ties setup to what SB-18 will show.

Costs: it adds a route and one more click away from the list. The preview column has to agree with SB-18's real tile design, which is not approved yet.
