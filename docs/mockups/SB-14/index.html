Project handbook: two layouts

Both sit inside the design-A shell from SB-7 and show /p/coins/handbook with real data: coins at origin/main 23679a5, the kit at ~/Code/dev-standards HEAD 29b7281. Option A: section tabs

A row of section tabs (Rules, Lessons, Standards, Runbook, Decisions, Skills) above one full-width reading card. Kit badges sit inline next to each file: a dot on each standards sub-tab, a chip in the file header, and a chip on each skill card. Lessons and runbook entries are an accordion, and a decision opens in the design-A centred modal.

Option B: document reader with a drift rail

The centre reads like a document: every lesson is open, and a decision opens in the reading pane with a back link. A right "Kit drift" rail sums up every badge on one card (a bar and counts, then each standards file and kit skill), and each row jumps to its file.

The trade-off

A is compact and fits the dashboard's tab rhythm, but drift is spread across the tabs, so you open Standards and Skills to see what differs. B shows the whole drift picture from any section and reads long files better, but it has three columns: the rail drops to a collapsible summary below 1280px, and the nav becomes a select on a phone.

Worth knowing before you pick

  • Badge colours reuse existing tokens: built (same as kit), warning (changed), danger (missing), cancelled (project only).
  • coins' runbook is 20,185 lines (974 entries), so both options show entries in batches rather than the whole file at once.
